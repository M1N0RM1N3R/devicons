Devicons is community-built. Every icon, metadata entry, and tooling improvement lands through pull requests on GitHub.

## Before you open a PR

1. Search first. Check the [icon library](/search) and open issues to avoid duplicates.
2. Follow the grid. Icons are drawn on a 24x24 grid with a 1.5px stroke by default. Larger marks use 2px.
3. Check brand guidelines. If the icon represents a company or product, link the guideline you followed.

## Adding an icon

Drop a single, optimized SVG into `packages/icons/src/<slug>.svg`. Then add metadata:

```yaml
---
name: "Your Icon"
description: "One sentence about what this represents."
icons: [your-icon]
tags: ["category", "related-keywords"]
website: "https://example.com"
---
```

Run the build to regenerate packages:

```bash
pnpm build
```

## Improving an existing icon

- Preserve the original icon IDs. They're public API.
- Match the visual weight of nearby icons. The new version should sit cleanly next to its siblings.
- Test both the colored and monochrome variants before opening the PR.

## Tooling

- `pnpm format` runs Prettier + SVGO
- `pnpm dev` starts this website locally with your changes
- `pnpm test:visual` catches regressions across the grid

## Code of conduct

Be kind. Assume good intent. Celebrate first-time contributors, even if their PR is just fixing a typo.
